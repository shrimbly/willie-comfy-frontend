<objective>
Persist `moshpitOverrideStore` (pinned world positions + manual scales) to IndexedDB so manual pins and resizes survive page reloads.

Purpose: Right now pins and scales are lost on every reload, making the "move-and-pin" interaction effectively ephemeral. Persistence turns it into a real curation gesture.

Output:

- `overrides` object store added to `MoshpitDB` at schema v4.
- New `overrideRepository.ts` service reusing the existing `thumbRepository` DB connection.
- `moshpitOverrideStore.hydrate()` boot action + debounced writes on every mutation.
- Unit tests for repository (fake-indexeddb) and store-persistence wiring (mocked repo, fake timers).
  </objective>

Existing `thumbRepository.ts` exposes an internal DB promise via `openDB<MoshpitDB>(MOSHPIT_DB_NAME, MOSHPIT_DB_VERSION, { upgrade })`. The override repository MUST reuse that same connection. Two options (executor picks whichever is smallest):

Option A — export the db accessor from `thumbRepository.ts`:

```ts
// add near the top of thumbRepository.ts
export function getMoshpitDB() {
  return dbPromise // existing lazy-singleton promise already in that file
}
```

Option B — move the `openDB(...)` call into a tiny shared module (e.g. `moshpitDb.ts`) that both `thumbRepository.ts` and `overrideRepository.ts` import. Only take this path if Option A is awkward; keep the diff minimal.

New `overrideRepository.ts` API (exact signatures — do not deviate):

```ts
export interface OverridePersistedRecord {
  contentHash: string
  pinnedWorldPos?: { x: number; y: number }
  scale?: number
  pinnedAt: number
}

export async function loadAllOverrides(): Promise<OverridePersistedRecord[]>
export async function saveOverride(
  record: OverridePersistedRecord
): Promise<void>
export async function deleteOverride(contentHash: string): Promise<void>
export async function clearAllOverrides(): Promise<void>
```

Schema changes in `thumbRepository.types.ts`:

```ts
export const MOSHPIT_DB_VERSION = 4 // was 3

export interface MoshpitDB extends DBSchema {
  // ...existing stores unchanged...
  overrides: {
    key: string // contentHash
    value: OverridePersistedRecord
  }
}
```

(Import `OverridePersistedRecord` as a `type` import from `./overrideRepository` — or redeclare the shape in `types.ts` and have the repository re-export it. Pick whichever avoids a circular import; if unsure, declare the record shape in `thumbRepository.types.ts` and import it from there in the repository.)

Upgrade branch (add to existing `upgrade(db, oldVersion)` in `thumbRepository.ts`, do NOT touch v2/v3 branches):

```ts
if (oldVersion < 4) {
  db.createObjectStore('overrides', { keyPath: 'contentHash' })
}
```

Store wiring (`moshpitOverrideStore.ts`):

- Add a `hydrate()` action that calls `loadAllOverrides()` and seeds the in-memory Map. Validate each record defensively (skip + `console.warn` if `contentHash` is missing or types are wrong — do NOT throw).
- Add a 100ms debounced persist per hash. Use `useDebounceFn` from `@vueuse/core` OR a tiny inline `setTimeout` debounce keyed by hash (either is fine; prefer the inline version if simpler to test with fake timers).
- On `setPin(hash, ...)` / `setScale(hash, ...)`: schedule `saveOverride({ contentHash: hash, pinnedWorldPos, scale, pinnedAt })`.
- On `unpin(hash)` / `clearScale(hash)`: if the resulting entry has neither pin nor scale, schedule `deleteOverride(hash)`; otherwise schedule `saveOverride(...)` with the remaining field.
- On `clear(hash)`: schedule `deleteOverride(hash)`.
- On `clearAll()`: schedule `clearAllOverrides()` (cancel any pending per-hash writes first).
- Swallow repository errors in a `.catch((err) => console.warn(...))` — persistence failures must NOT break in-memory behaviour.
