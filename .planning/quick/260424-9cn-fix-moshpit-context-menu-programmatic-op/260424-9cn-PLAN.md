<objective>
Fix two Moshpit canvas-overlay bugs diagnosed by the user:

1. **Context menu does not open programmatically.** `MoshpitSpriteContextMenu.vue` uses Reka UI `ContextMenuRoot`, which only renders via a native `contextmenu` event on its `Trigger`. `MoshpitView.onContextMenu` handles the right-click itself (it needs the sprite hit-test) and calls `spriteContextMenuRef.value?.open(x, y, hash)`, which flips `isOpen` to `true` — but Reka's ContextMenu ignores that. Swap to `DropdownMenu`, which supports `v-model:open`. The component's own test file already documents this limitation; tests drive the callbacks via `defineExpose`, not DOM, so they keep passing after the swap.

2. **Floating action bar is off-brand.** `MoshpitFloatingActionBar.vue` uses `rounded-full`, `border-border-subtle`, `bg-interface-panel-surface`, and raw `<button>` with a `focus-visible:ring-2 focus-visible:ring-(--focus-ring)` — this reads as a pill with a dual-colored outline ring. Rebuild it as a rectangular toolbar matching `src/components/graph/GraphCanvasMenu.vue` (the canonical ComfyUI floating toolbar): `border border-interface-stroke bg-comfy-menu-bg p-2`, with `<Button variant="secondary">` children (`@/components/ui/button/Button.vue`) and `h-[27px] w-px self-center bg-node-divider` separators. No new PrimeVue imports — compose layout with plain `<div>` + Tailwind (do NOT copy GraphCanvasMenu's `ButtonGroup` wrapper).

Purpose: Restore right-click context-menu functionality (regressed at ship of quick task 260423-kx4) and align Moshpit overlays to native ComfyUI toolbar styling.

Output: Two files modified, one atomic commit per task, existing Vitest suites for both components green without modification.
</objective>
