<objective>
Foundation layer for sprite controls on the Moshpit canvas: introduce a per-asset override data model (pinned world position + scale) and wire it through the sprite renderer so pinned/resized sprites already work end-to-end before any UI ships. No context menu, no action bar, no drag-to-pin — just the underlying store + rendering integration with tests.

Purpose: De-risk the controls feature by landing the hot path (store → sprite position + scale + selection ring) in isolation. Every subsequent quick task (context menu, floating action bar, drag-to-pin, resize handles, copy/paste, download, hide-others) plugs into this store without touching the renderer again.

Output: A new `moshpitOverrideStore` Pinia store, a small set of modifications to `useMoshpitSpriteLayer` that layer overrides over the injected `layoutProvider` output, and co-located behavioural tests.
</objective>

  <behavior>
    - setPin(hash, {x, y}) → store.get(hash) returns record with pinnedWorldPos matching; isPinned(hash) true; size increments for a new hash
    - setPin on an existing record preserves `scale` if previously set; pinnedAt is refreshed (Date.now() based, monotonic non-decreasing within a test)
    - setScale(hash, 1.5) without prior record creates a record with scale=1.5, no pinnedWorldPos, isPinned false
    - setScale on an existing pinned record preserves pinnedWorldPos
    - unpin(hash) removes pinnedWorldPos but keeps the record if scale is still set; if only pin existed, record is removed and size decrements
    - clearScale(hash) removes scale but keeps pinnedWorldPos; removes record entirely if nothing else remains
    - clear(hash) removes the whole record regardless of contents
    - clearAll() / reset() empties the map; size === 0
    - Reactivity: after any mutation the underlying Map reference changes (snapshot captured before vs after mutation is not the same object) so watchEffect on `store.get(hash)` style reads re-fires
    - get() for an unknown hash returns undefined
  </behavior>
  <action>
    Create `src/platform/moshpit/stores/moshpitOverrideStore.ts`:
    - Model after `moshpitSelectionStore.ts` shape (new Set → new Map pattern).
    - `export interface OverrideRecord { readonly pinnedWorldPos?: { x: number; y: number }; readonly scale?: number; readonly pinnedAt: number }`.
    - Private state: `const records = ref<Map<string, OverrideRecord>>(new Map())`.
    - `size = computed(() => records.value.size)`.
    - `get(hash): OverrideRecord | undefined` reads `records.value.get(hash)`.
    - `isPinned(hash): boolean` returns `!!get(hash)?.pinnedWorldPos`.
    - `setPin(hash, worldPos: { x: number; y: number })`: clone map, merge/create record preserving existing `scale`, set `pinnedWorldPos: { ...worldPos }` (defensive copy to avoid caller-mutation), update `pinnedAt = Date.now()`, reassign `records.value`.
    - `setScale(hash, scale: number)`: clone map, merge/create record preserving existing `pinnedWorldPos`, set `scale`, update `pinnedAt = Date.now()`, reassign.
    - `unpin(hash)`: if record exists and has `pinnedWorldPos`, clone map, rebuild record without `pinnedWorldPos`; if remaining record has no `scale` and no `pinnedWorldPos`, delete the key; reassign.
    - `clearScale(hash)`: mirror of `unpin` for the `scale` field.
    - `clear(hash)`: clone map, `delete(hash)`, reassign (no-op if absent).
    - `clearAll()`: reassign to `new Map()` if size > 0.
    - `reset()`: alias for `clearAll()` to match the `moshpitCurationStore.reset()` / `moshpitTournamentStore.reset()` convention (phase-reset callsites use `reset()`).
    - Module surface: export only the two symbols (`useMoshpitOverrideStore`, `OverrideRecord`). No barrel re-exports.
    - No `any`, no `as any`. Use `readonly` on the exported type fields. Use function declarations, not arrow function expressions, where feasible (AGENTS.md #24).

    Create `src/platform/moshpit/stores/moshpitOverrideStore.test.ts`:

    - Cover every behaviour in the `<behavior>` block. Behavioural, not change-detector — assert observed state via public getters, not internal refs.
    - For reactivity, capture `records` container identity by calling `store.get(hash)` before/after and by confirming `store.size` updates; do not reach into `store.$state` directly except to capture the Map reference for identity comparison if needed.
    - Keep the file under ~120 lines. No test-only API additions to production code.
