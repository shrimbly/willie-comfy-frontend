# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: Filter & Sort (Core Validation).
> Five surfaces in scope: initial-filter gate section, filter chip rail, sort controls,
> axis-label overlay on canvas, and Settings panel structural extension.
> Generated by gsd-ui-researcher. Extends Phase 2 design contract.

---

## Design System

| Property          | Value                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Tool              | none — no shadcn; Tailwind 4 + existing semantic tokens                                                                   |
| Preset            | not applicable                                                                                                            |
| Component library | Reka UI (ComboboxRoot for workflow picker; PopoverRoot for add-filter picker; SliderRoot for grid-spacing control)        |
| Icon library      | Iconify via `icon-[lucide--*]` (unplugin-icons — `lucide--plus`, `lucide--x`, `lucide--chevron-down`, `lucide--grid-2x2`) |
| Font              | System font stack (inherited from ComfyUI shell — no new font)                                                            |

**Source:** Phase 2 design contract `02-UI-SPEC.md`; RESEARCH.md §Standard Stack; existing Moshpit components.

---

## Spacing Scale

8-point base scale, multiples of 4px. All values map to existing Tailwind 4 utility classes.

| Token | Value                 | Usage                                                                                        |
| ----- | --------------------- | -------------------------------------------------------------------------------------------- |
| xs    | 4px (`p-1`, `gap-1`)  | Gap between chip label and remove icon; gap between filter section label and controls        |
| sm    | 8px (`p-2`, `gap-2`)  | Internal chip padding; gap between sort X and Y picker; internal popover item padding        |
| md    | 12px (`px-3`, `py-2`) | Settings panel horizontal padding (inherits existing `px-3 py-2` pattern from Phase 2)       |
| lg    | 16px (`gap-4`)        | Gap between Settings panel sections (filter gate, chip rail, sort controls, footer controls) |
| xl    | 24px (`py-6`)         | Canvas empty-state vertical centering offset                                                 |
| 2xl   | 32px                  | Not used in Phase 3 surfaces                                                                 |
| 3xl   | 64px                  | Not used in Phase 3 surfaces                                                                 |

Exceptions:

- Filter chip remove button: 20px × 20px minimum hit target (`size-5`). Chips are dense UI inside the Settings panel; 32px would make the chip rail impractically tall. The panel-scoped context (not primary interactive surface) justifies the reduced target.
- Workflow picker trigger: full-width, height 32px (`h-8`) — matches existing `size: md` button height in `button.variants.ts`.
- Grid-spacing slider thumb: inherits `Slider.vue` default — do not declare a size in this spec. (`Slider.vue` uses `size-3.5` internally; that is a component implementation detail, not a contract value for this phase.)
- Axis labels on canvas: 12px left/4px vertical padding (`px-3 py-1`) inside a pill-shaped overlay label.

---

## Typography

Four roles, two weights — all from existing Tailwind 4 scale. Extends Phase 2 vocabulary (body 12px, caption 10px).

| Role           | Size              | Weight        | Line Height | Usage                                                                                             |
| -------------- | ----------------- | ------------- | ----------- | ------------------------------------------------------------------------------------------------- |
| Body / Label   | 12px (`text-xs`)  | 400 (regular) | 1.5         | Filter chip text; sort picker labels; grid-spacing footer row label; "Show hidden" toggle label   |
| Section header | 10px (`text-2xs`) | 500 (medium)  | 1.6         | Settings panel section titles: "Filter", "Sort", "Grid spacing" — uppercase, letter-spacing tight |
| Axis label     | 12px (`text-xs`)  | 500 (medium)  | 1.4         | Canvas axis overlay column/row headers — e.g., "CFG 7.5", "euler" — must be legible at min zoom   |
| Workflow count | 12px (`text-xs`)  | 400 (regular) | 1.5         | Count suffix in workflow picker option: " (1,247 assets)" in `text-muted-foreground`              |

**Notes:**

- Section headers use `text-2xs` (10px) + `font-medium` + `uppercase tracking-wider` to create visual hierarchy inside the 64px-wide settings panel without consuming vertical space.
- Axis label uses `font-medium` (500) because it must remain legible at reduced canvas zoom where `text-xs` at regular weight could drop below perceptual contrast threshold.
- No heading size (`text-sm` 14px or above) is needed for Phase 3 surfaces — all chrome is within the Settings panel or the axis overlay, both at utility density.

**Source:** Phase 2 `02-UI-SPEC.md` §Typography; `MoshpitSettingsPanel.vue` header uses `text-sm`; section labels one step smaller to stay subordinate to the panel header.

## Color

Phase 3 adds no new color tokens. All new chrome maps to existing semantic tokens.

### Color contract (60/30/10)

| Role            | Tailwind / CSS token          | Usage                                                                                                            |
| --------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `bg-interface-panel-surface`  | Settings panel body, popover backgrounds, workflow picker dropdown                                               |
| Secondary (30%) | `bg-secondary-background`     | Filter chip pill background at rest; sort picker trigger at rest; section dividers; slider track                 |
| Accent (10%)    | `bg-primary-background`       | Active filter chips (chips with a value set — not the "+ Add filter" button); sort axis label overlay background |
| Destructive     | `text-destructive-background` | Not used in Phase 3 — no destructive actions                                                                     |

**Accent reserved for:**

1. Active filter chip pill background (`bg-primary-background` or `bg-secondary-background-selected` — see chip states below)
2. Sort axis label overlay pill background (distinguishes axis labels from canvas content)
3. Active sort axis picker selected-value highlight

No other elements use the accent token in Phase 3.

### Component-level color spec

#### Filter chip pill (active — has a value set)

| State      | Background                            | Text                   | Remove icon                  | Border |
| ---------- | ------------------------------------- | ---------------------- | ---------------------------- | ------ |
| Default    | `bg-secondary-background`             | `text-base-foreground` | `text-muted-foreground`      | none   |
| Hover      | `hover:bg-secondary-background-hover` | `text-base-foreground` | `hover:text-base-foreground` | none   |
| Focus ring | —                                     | —                      | `focus-visible:ring-2`       | —      |

**Note on chip color choice:** Phase 2 uses `bg-interface-panel-surface` for the processing pill (it sits on the canvas). Phase 3 filter chips live inside the Settings panel (which is already `bg-node-component-surface`). Using `bg-secondary-background` for chips creates the necessary figure/ground separation within the panel without reaching for the accent color. Reserve accent (`bg-secondary-background-selected` or `bg-primary-background`) for when a chip is in an edited/errored state, or for the active sort axis pill — both are higher-signal UI moments.

#### "+ Add filter" button

| State   | Background                | Text                    |
| ------- | ------------------------- | ----------------------- |
| Default | transparent               | `text-muted-foreground` |
| Hover   | `bg-secondary-background` | `text-base-foreground`  |

Uses `variant="muted-textonly"` from existing `button.variants.ts`.

#### Workflow picker trigger

| State  | Background                      | Text                    | Border                  |
| ------ | ------------------------------- | ----------------------- | ----------------------- |
| Empty  | `bg-secondary-background`       | `text-muted-foreground` | `border-border-subtle`  |
| Filled | `bg-secondary-background`       | `text-base-foreground`  | `border-border-subtle`  |
| Open   | `bg-secondary-background-hover` | `text-base-foreground`  | `border-border-default` |

#### Sort axis picker

Same visual treatment as workflow picker trigger. When a sort axis is active (value selected), the picker trigger displays the selected value in `text-base-foreground`. When Y-axis has no value, the "+ Add axis" affordance uses `text-muted-foreground`.

#### Canvas axis overlay labels

| State   | Background                   | Text                   | Border                    |
| ------- | ---------------------------- | ---------------------- | ------------------------- |
| Default | `bg-interface-panel-surface` | `text-base-foreground` | `border-interface-stroke` |

Labels are pill-shaped (`rounded-full`) to distinguish them from canvas sprite content.

#### "Show hidden" toggle and grid-spacing footer area

Shares the `px-3 py-2` Settings panel padding. Toggle uses `bg-secondary-background` track, `bg-primary-background` thumb when on — inherits `Slider.vue`/toggle pattern. No custom tokens needed.

**Source:** Phase 2 color contract; `button.variants.ts` for button color semantics; existing `Slider.vue` uses `bg-node-stroke` track and `bg-node-component-surface-highlight` fill — Phase 3 may use the same for the grid-spacing slider.

## Component Specs

### Surface 1: Settings Panel Structure Extension

**File:** `src/platform/moshpit/components/MoshpitSettingsPanel.vue` (extended)

**Primary visual anchor:** The filter chip row is the core Phase 3 interaction surface — it is the most visually dense new element and the focal point users will interact with after selecting a workflow.

**Section order (top to bottom):**

```
MoshpitSettingsPanel
├── [header row]           "Settings" label (existing)
├── [section: Filter]
│   ├── MoshpitWorkflowPicker    (initial gate — always visible)
│   ├── MoshpitTimeRangePicker   (initial gate — always visible)
│   ├── [divider]
│   └── MoshpitFilterChipRow     (chips + "+ Add filter" button — gated: hidden until workflow set)
├── [divider]
├── [section: Sort]              (gated: hidden until workflow set)
│   └── MoshpitSortControls
├── [divider]
├── [section: footer controls]   (always visible)
│   ├── grid-spacing slider row  (gated: only interactive when sort is active)
│   └── show-hidden toggle row
└── [existing excluded-count row]
```

**Gating rule:** The filter chip row, sort section, and grid-spacing slider are hidden (`v-if`) until `moshpitFilterStore.workflow !== null`. The workflow picker and time-range picker render unconditionally. This implements D-06: "Settings panel only gate" where the canvas empty state drives the user to the top of the Settings panel.

**Overflow:** `overflow-y-auto` on the flex-1 scroll container (existing) handles tall chip lists.

**File:** `src/platform/moshpit/components/MoshpitWorkflowPicker.vue` (new)

**Pattern:** Reka UI `ComboboxRoot` / `ComboboxInput` / `ComboboxContent` / `ComboboxItem` — same primitives as `SearchAutocomplete.vue`.

```
MoshpitWorkflowPicker
```

#### Geometry

```

  width: 100% (w-full — fills px-3 panel padding)
  height: 32px (h-8)
  padding: px-2 (8px horizontal)
  border: border border-border-subtle rounded-md
  display: flex items-center justify-between gap-2

dropdown:
  width: 100% of trigger (w-full)
  max-height: 240px (max-h-60) — 5 items at 48px each
  border: border border-border-subtle rounded-md
  background: bg-interface-panel-surface
  shadow: shadow-interface

  height: 32px (h-8)
  padding: px-2 py-1
  border-bottom: border-b border-border-subtle
  background: transparent
  sticky: position sticky top-0

item:
  height: 40px (h-10) — comfortable touch-target for dense list
  padding: px-2 (8px)
  display: flex items-center justify-between
  hover: bg-secondary-background-hover

count suffix:
  text-muted-foreground text-xs
  suffix format: " (N assets)" where N is comma-formatted
```

#### Placeholder copy

- Empty (no workflow selected): `"Select a workflow…"` — `text-muted-foreground`
- With selection: workflow name in `text-base-foreground`

#### Keyboard

- `↓` / `↑` navigate items; `Enter` selects; `Esc` closes; search input receives focus on open.
- Reka UI `ComboboxRoot` provides all keyboard navigation — no custom key handling needed.

#### Accessibility


### Surface 8: MoshpitAxisOverlay

**File:** `src/platform/moshpit/components/MoshpitAxisOverlay.vue` (new)

**Mounting:** Inside `MoshpitCanvas.vue` as an absolute overlay layer, sibling to the PixiJS canvas element. Pointer-events: none (labels are display-only, not interactive).

**Visibility:** `v-if="sortX !== null"` — only renders when a sort is active.

#### Architecture

The overlay tracks world-space column/row coordinates by subscribing to the `pixi-viewport` `moved` event (same event `MoshpitCanvas.vue` already subscribes to). On each `moved` event, it calls `viewport.toScreen(worldX, 0)` for each column to get the screen-space X position, then sets CSS `left` on each label.

Viewport is injected via `MOSHPIT_VIEWPORT_INJECTION_KEY` (not prop-drilled). Labels only render when the injection key is non-null (after viewport init).

#### X-axis column labels (1D and 2D)

```
axis-label pill:
  position: absolute
  left: computed from viewport.toScreen(column.worldX + gridSpacing/2, 0).x   (centered over column)
  top: 8px   (distance from canvas top edge; outside any sprite region since sort layout starts at y=0)

  style:
    bg-interface-panel-surface border border-interface-stroke rounded-full
    px-3 py-1 text-xs font-medium text-base-foreground
    shadow-interface
    white-space: nowrap
    transform: translateX(-50%)   (center-align over column)
    pointer-events: none

  content: formatAxisLabel(column.paramValue, sortX)
    — numeric: raw value (e.g., "7.5")
    — categorical: value as-is (e.g., "euler")
    — timestamp (time-range): formatted date "Apr 21"
    — loras (count): "N LoRA" / "N LoRAs"
```

#### Y-axis row labels (2D only, v-if sortY !== null)

```
axis-label pill:
  position: absolute
  left: 8px   (near left edge of canvas area)
  top: computed from viewport.toScreen(0, row.worldY + gridSpacing/2).y   (centered on row)
  transform: translateY(-50%)
  — same pill style as X-axis
  — truncated to 16 characters with ellipsis if categorical value is long
```

#### Performance

Label count = number of unique values for the sort axis. Maximum reasonable: ~50 columns (e.g., seed values across a wide sweep). Each `moved` event updates `N` CSS `left` values — trivially within 1ms. No canvas redraws needed; HTML overlay handles its own positioning.

## Motion

All new Phase 3 animations are additive to the Phase 2 vocabulary. No new easing curves.

| Event                               | Duration | Easing           | Mechanism                                                                                     |
| ----------------------------------- | -------- | ---------------- | --------------------------------------------------------------------------------------------- |
| Filter chip add                     | 300ms    | ease-out-cubic   | Sprite layer tween (Phase 2 primitive) — canvas sprites move; chip appears instantly in panel |
| Filter chip remove                  | 300ms    | ease-out-cubic   | Sprites tween back to visible positions; chip disappears instantly                            |
| Sort axis set / change              | 300ms    | ease-out-cubic   | Sprites tween to sorted column positions; axis overlay labels fade in 150ms                   |
| Sort cleared (return to chaos)      | 300ms    | ease-out-cubic   | Sprites tween back to jittered grid; axis overlay labels fade out 150ms                       |

**Rule:** All sprite position changes use the 300ms ease-out-cubic tween path in `useMoshpitSpriteLayer`. UI chrome (chips, labels, popover) uses standard CSS transitions. No new Ticker-driven HTML animations.

## Open Questions

### OQ-1: Figma coverage gap (carried from Phase 2)

Phase 2 OQ-1 identified no Moshpit-specific tokens in the Comfy Design Standards Figma (`QreIv5htUaSICNuO2VBHw0`). Phase 3 introduces the filter chip, sort control, and axis overlay — all more prominent UI chrome than Phase 2's utility indicators.

**Resolution:** Contract derived from existing semantic tokens (`bg-secondary-background`, `bg-interface-panel-surface`, `border-border-subtle`, etc.) and the established Phase 2 pattern precedent. Before Phase 4 (comparison toolbar is more prominent), recommend designer review of the Moshpit UI family and possible Figma additions.

**Action:** Researcher notes this as a design-debt item. Planner does not need to block on it.

### OQ-2: Reka UI Switch component availability

The "Show hidden" toggle spec uses a custom-styled `<input type="checkbox">` or Reka UI Switch. `src/components/ui/` does not contain a Switch component as of Phase 2.

**Resolution:** Implement as a custom-styled checkbox with `appearance-none` and CSS pseudo-elements for the track/thumb. Matches the Reka UI `SwitchRoot` pattern but avoids a new component file for a single toggle. If a Switch component exists by Phase 3 execution time, use it instead.

**Action:** Executor checks `src/components/ui/` for a Switch component before implementing. If found, use it. If not, implement inline styled checkbox — do NOT create a new `Switch.vue` for Phase 3 only.

### OQ-3: Workflow identifier for picker (carried from RESEARCH.md)

RESEARCH.md §Open Questions §1 documents that `AssetItem.user_metadata` contains no stable workflow filename, and the `prompt` chunk contains no filename (D-02 prohibits walking `workflow` chunk).

**Resolution for UI-SPEC purposes:** The workflow picker display format `"[topology fingerprint] (N assets)"` is the locked format. The exact fingerprint derivation (sorted class_type set) is a planner-level concern, not a UI contract question. The picker visual spec is identical regardless of the fingerprint strategy.

**Action:** Planner resolves the fingerprint strategy in the param-extraction plan.

### OQ-4: Chip rail reorder / edit

Phase 3 does not spec chip reordering (drag-to-reorder) — chips are unordered (AND semantics across chips means order doesn't affect filter result). No drag-handle UI needed.

Editing an existing chip: clicking the chip label (not the × button) re-opens the add-filter popover in Step 2 (value editor) pre-populated with the chip's current value. This is a nice-to-have; the minimum spec is click-to-remove only. Executor ships click-to-remove; edit-on-click can be a gap-closure task.
