**Step C — thumbRepository.ts (v1→v2 upgrade):**

The `upgrade` callback now receives `(db, oldVersion, newVersion, transaction)`. For `oldVersion < 2`, iterate every record in `assetMeta` and re-parse its `params` field using `normalizeParams(record.metadata, fallbackTimestamp)` — timestamp fallback must come from the metadata itself if available; otherwise use `0` and rely on the next warm-cache write to overwrite.

```typescript
import { normalizeParams } from './paramNormalize'
// ...

export function openMoshpitDB(): Promise<IDBPDatabase<MoshpitDB>> {
  if (cachedDB) return cachedDB
  cachedDB = openDB<MoshpitDB>(MOSHPIT_DB_NAME, MOSHPIT_DB_VERSION, {
    async upgrade(db, oldVersion, _newVersion, tx) {
      if (!db.objectStoreNames.contains('thumbs')) {
        db.createObjectStore('thumbs', { keyPath: 'contentHash' })
      }
      if (!db.objectStoreNames.contains('assetMeta')) {
        db.createObjectStore('assetMeta', { keyPath: 'contentHash' })
      }
      // v1 → v2: retroactively populate `params` on existing assetMeta records.
      // Plain await inside idb's upgrade — tx is the version-change transaction.
      if (oldVersion < 2) {
        const store = tx.objectStore('assetMeta')
        let cursor = await store.openCursor()
        while (cursor) {
          const rec = cursor.value
          // Guard: records already written at v2 (unlikely in this branch but safe)
          if (!('params' in rec)) {
            const nowFallback = Date.now()
            const params = normalizeParams(rec.metadata, nowFallback)
            await cursor.update({ ...rec, params })
          }
          cursor = await cursor.continue()
        }
      }
    },
    blocked() { /* existing */ },
    terminated() { /* existing */ }
  })
  return cachedDB
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker → main thread | `ThumbReadyMessage` cloned structured — no executable payloads |
| IDB → main thread | `AssetMetaRecord` read; now includes `params` which is already-narrowed output of normalizeParams |
| Prior-session IDB v1 record → v2 migration | Untrusted stored data; migration re-parses via normalizeParams which has its own hardening |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04-01 | Tampering | IDB upgrade migration crash on malformed v1 record | mitigate | normalizeParams returns emptyParams on any parse failure (see Plan 03-01 T-03-01-01); migration wraps the re-parse per-record so a single bad record can't abort the whole upgrade |
| T-03-04-02 | Denial of Service | v1→v2 migration stalls on huge IDB (thousands of records) | accept | Bounded by user's thumb cache size; migration runs once per upgrade; no network egress; uses cursor-based streaming (does not load all records into memory) |
| T-03-04-03 | Tampering | Race between two tabs — tab A at v2 writes while tab B still at v1 reads | mitigate | `blocked()` handler in openDB already logs warning; `idb` serializes version upgrades; v2 reads reject v1 schema via TypeScript — runtime fallback is `record.params ?? normalizeParams(record.metadata, Date.now())` in the repository layer IF read-time narrowing is needed (add as a belt-and-braces check) |
| T-03-04-04 | Information Disclosure | Prompt text persisted in IDB | accept | Same as Plan 03-02 T-03-02-01 — local-only storage; no new exposure vs Phase 2 |
</threat_model>
