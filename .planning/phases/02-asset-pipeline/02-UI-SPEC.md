# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2: Asset Pipeline.
> Two surfaces in scope: `MoshpitProcessingIndicator` (bottom-left canvas overlay pill) and the excluded-count row in `MoshpitSettingsPanel`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Pattern precedent note:** These two elements establish the first indicator/overlay UX pattern for Moshpit. The positioning convention, progress-bar visual spec, icon-button cancel affordance, and info-tooltip trigger pattern defined here are the canonical reference for Phase 3+ (filter chips, sort affordances, comparison toolbar).

## Spacing Scale

Declared values (multiples of 4, matching Tailwind 4 convention):

| Token | Value                | Usage                                                                                                                  |
| ----- | -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| xs    | 4px (`p-1`, `gap-1`) | Icon-to-label gap inside pill; gap between info icon and label text                                                    |
| sm    | 8px (`p-2`, `gap-2`) | Pill internal horizontal padding between text and `×` button                                                           |
| md    | 12px (`p-3`, `px-3`) | Pill horizontal padding left/right edges; Settings panel row horizontal padding (matches existing `px-3 py-2` pattern) |
| lg    | 16px (`gap-4`)       | Pill margin from canvas edges (bottom: 16px, left: 16px — see Layout section)                                          |
| xl    | 24px                 | Not used in Phase 2 surfaces                                                                                           |

Exceptions:

- `×` cancel button: 32px × 32px minimum hit target (Tailwind: `size-8` = 32px), overriding the natural icon size of 16px (`size-4`). This satisfies the Figma Click Targets spec (node ID `4:243`).
- Info icon hit target: 24px × 24px (`size-6`) inline — small but non-interactive beyond tooltip trigger; acceptable for a read-only affordance.

**Source:** Existing `MoshpitSettingsPanel.vue` uses `px-3 py-2`; `MoshpitSideRail.vue` uses `p-1 gap-1`. Click target sizing from Comfy Design Standards Figma `4:243`.

## Component Specs

### Surface 1: MoshpitProcessingIndicator

**Component file:** `src/platform/moshpit/components/MoshpitProcessingIndicator.vue`

**Mount point:** `MoshpitLayout.vue` — absolute-positioned overlay child (added to the `<main>` canvas container, NOT inside the sidebar or side-rail). The pill must appear regardless of Settings panel open/closed state.

#### Structure

```
MoshpitProcessingIndicator (pill container)
├── Row 1: [count text] ["Processing {done} / {total}"]  [× cancel button]
└── Row 2: progress bar  [track] [fill: width = done/total * 100%]
```

#### Geometry

```
pill:
  width: auto (shrink-fits to content; min-width: 180px)
  height: auto (2 rows + internal padding)
  border-radius: rounded-lg (8px)
  padding: px-3 py-2 (12px horizontal, 8px vertical)
  gap between rows: gap-1 (4px)

progress bar:
  height: 2px (h-0.5)
  width: 100% of pill content width
  border-radius: rounded-full
  track: bg-secondary-background
  fill: bg-[--color-interface-panel-job-progress-primary]
  transition: width 300ms ease-out (driven by done/total reactivity)

cancel button (×):
  size: size-8 (32px × 32px) — minimum hit target
  icon: icon-[lucide--x] size-4 (16px) — centered within hit target
  border-radius: rounded-md (6px)
  focus ring: focus-visible:ring-2 focus-visible:ring-[--interface-stroke] focus-visible:ring-offset-1
  hover: hover:bg-secondary-background hover:text-base-foreground
  cursor: cursor-pointer
```

#### Positioning (canvas corners convention — Phase 3+ inherits this)

```
position: absolute
bottom: 16px  (m-4 = 16px from the canvas container bottom edge)
left: 16px    (m-4 = 16px from the canvas container left edge)
z-index: z-50 (above PixiJS canvas; below any future modal layer)
```

The pill is anchored to the **canvas container** (`MoshpitLayout`'s center canvas area), not the browser viewport. This keeps it correctly placed when the Settings panel opens/closes.

**Why `absolute` not `fixed`:** The `MoshpitLayout` canvas area is the positioning context. Using `absolute` within the canvas overlay div ensures the pill moves with the canvas region if the panel collapses, rather than staying viewport-fixed and potentially overlapping the sidebar.

#### States

| State        | Condition                               | Visual                                                                                                                               |
| ------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `hidden`     | `total === 0` OR warm-cache path (D-08) | Component not rendered (`v-if="isVisible"`)                                                                                          |
| `processing` | `total > 0 && done < total`             | Full opacity, progress fill animating, `×` visible                                                                                   |
| `completing` | `done === total && total > 0`           | Full opacity + 100% fill for 600ms, then `opacity-0` transition over 200ms                                                           |
| `cancelling` | `×` clicked, worker abort in-flight     | Pill remains visible at current done/total (no micro-state copy change — dismiss immediately on click and let store reset handle it) |

**Cancelling call (locked):** Click `×` → emit `cancel` immediately → parent calls worker abort → pill stays mounted until store resets `total` to 0 (which triggers `hidden`). No "Cancelling…" copy change. The pill disappears when the store resets. This avoids a flash from a transient "Cancelling…" string and keeps the state machine simple.

#### Interaction

- Click `×` → `emit('cancel')` — parent `MoshpitLayout` calls `processingQueue.cancel()` which calls `workerBridge.cancelAll()`.
- The pill itself is non-draggable. No click-outside-dismiss. No expand-on-hover.
- `×` button: `Enter` and `Space` trigger cancel (native button behavior).
- Tab order: `×` button is focusable. It receives focus after the last focusable element in the Settings panel when the panel is open. When the panel is collapsed, it is the first focusable element in the canvas area.

#### Accessibility

```html
<div
  role="status"
  aria-live="polite"
  aria-atomic="false"
  aria-label="Asset processing progress"
>
  <span>{{ t('moshpit.assets.processing', { done, total }) }}</span>
  <button
    :aria-label="t('moshpit.assets.cancel')"
    type="button"
    @click="$emit('cancel')"
  >
    <i class="icon-[lucide--x] size-4" aria-hidden="true" />
  </button>
  <!-- progress bar: presentational, not interactive -->
  <div
    role="progressbar"
    :aria-valuenow="done"
    :aria-valuemin="0"
    :aria-valuemax="total"
    :aria-label="t('moshpit.assets.processing', { done, total })"
  >
    <div :style="{ width: `${(done / total) * 100}%` }" />
  </div>
</div>
```

`aria-live="polite"` announces count changes without interrupting screen reader narration. `aria-atomic="false"` allows partial updates. The progress bar uses `role="progressbar"` with explicit `aria-valuenow/min/max`.

### Surface 2: MoshpitSettingsPanel excluded-count row

**Component file:** `src/platform/moshpit/components/MoshpitSettingsPanel.vue` (modified)

**Mount point:** Inside the `<div class="flex-1 overflow-y-auto px-3 py-2 text-xs">` section of the existing scaffold, immediately below where Phase 3 filter chips will appear (add a comment marker so Phase 3 knows where chips go above).

#### Structure

```
excluded-count row (v-if="excludedCount > 0")
├── span: "{N} assets excluded: no metadata"
└── button (icon-only): info icon + tooltip
```

#### Geometry

```
row container:
  display: flex items-center gap-1
  padding: none (inherits px-3 py-2 from parent scroll container)
  no border, no background

info icon:
  icon: icon-[lucide--info]
  size: size-3.5 (14px — optical match for text-xs context)
  color: text-muted-foreground
  cursor: cursor-help (signals tooltip, not click action)
  no hit-target expansion needed (non-interactive beyond tooltip display)
```

#### Tooltip spec

- **Trigger:** `v-tooltip` PrimeVue directive — consistent with existing repo tooltip pattern (verified in `SidebarIcon.vue`, sidebar tabs).
- **Placement:** `v-tooltip.top` — float above the icon (bottom of Settings panel placement would be cut off).
- **Content:** `t('moshpit.assets.excludedTooltip')` — "Assets are excluded because they don't contain parseable ComfyUI metadata. Moshpit only renders generated images with embedded workflow data."
- **No new tooltip component** — `v-tooltip` directive is already configured globally in the app (PrimeVue directive registration confirmed in existing sidebar tab usage).

#### Accessibility

```html
<div v-if="excludedCount > 0" class="flex items-center gap-1">
  <span :id="excludedDescId">
    {{ t('moshpit.assets.excludedCount', { count: excludedCount }) }}
  </span>
  <i
    class="icon-[lucide--info] size-3.5 cursor-help text-muted-foreground"
    role="img"
    :aria-label="t('moshpit.assets.excludedTooltipLabel')"
    :aria-describedby="excludedDescId"
    v-tooltip.top="t('moshpit.assets.excludedTooltip')"
  />
</div>
```

`aria-describedby` links the icon to the count text so a screen reader announcing the icon's `aria-label` also surfaces the count in context.

## Motion

All durations lock in the Moshpit animation vocabulary for Phase 3+.

### MoshpitProcessingIndicator motion

| Event                     | Duration | Easing     | Mechanism                                                                      |
| ------------------------- | -------- | ---------- | ------------------------------------------------------------------------------ |
| Pill mount (first appear) | 200ms    | `ease-out` | Tailwind `transition-opacity duration-200` — opacity 0→1                       |
| Pill completion: hold     | 600ms    | —          | `setTimeout` in component before fade starts                                   |
| Pill completion: fade     | 200ms    | `ease-out` | `transition-opacity duration-200`, opacity 1→0; `v-if` unmounts at 800ms total |
| Progress bar fill change  | 300ms    | `ease-out` | `transition-[width] duration-300 ease-out` on the fill `<div>`                 |
| Pill cancel               | 0ms      | —          | Immediate: store reset drives `v-if` unmount; no fade on cancel                |

**Implementation note:** The 600ms + 200ms completion sequence uses two `setTimeout` calls (as shown in RESEARCH.md §8):

- `setTimeout(() => { isFading.value = true }, 600)` — starts CSS opacity transition
- `setTimeout(() => { emit('done') }, 800)` — parent `v-if` unmounts

The re-pack canvas tween (D-04, 300ms ease-out-cubic via Pixi Ticker) fires at the same moment the 600ms hold begins, so: sprites tween to packed positions while pill is at 100% opacity, then pill fades — visually correct sequencing.

### Excluded-count row motion

No animation. The row appears/disappears instantly with `v-if="excludedCount > 0"`. Animating a count row in a settings panel is unnecessary chrome for a utility datum.

## Layout and Positioning

### Canvas overlay positioning convention (locks for Phase 3+)

```
MoshpitLayout canvas area: position: relative (or absolute inset-0)
  └── canvas overlay slot: absolute inset-0 pointer-events-none
        └── MoshpitProcessingIndicator: absolute bottom-4 left-4 pointer-events-auto
        └── (Phase 3+ overlays go in additional corners: top-right, bottom-right, etc.)
```

**Z-index ladder (Moshpit-specific, locks for Phase 3+):**

| Layer             | Z-index  | Content                                          |
| ----------------- | -------- | ------------------------------------------------ |
| PixiJS canvas     | base     | Sprite rendering                                 |
| Canvas overlays   | `z-50`   | Processing pill, Phase 3+ toolbar indicators     |
| Selection overlay | `z-50`   | `MoshpitMarqueeOverlay` (existing)               |
| Modals / dialogs  | `z-1700` | Comparison mode, Generate More modal (Phase 4/6) |

**Why `z-50`:** Matches the repo's pattern for non-blocking overlays (e.g., `AssetsSidebarGridView.vue` marquee uses `z-50`). The pill must not compete with future modal layers.

### Desktop-only math

Moshpit is explicitly desktop-first (PROJECT.md constraint). No responsive breakpoints needed for Phase 2 surfaces.

**Minimum canvas area considerations:**

- Settings panel open: canvas area = `100vw - sidebar-rail-width - settings-panel-width` = `100vw - 40px - 256px` = `100vw - 296px`. At 1280px viewport (minimum reasonable desktop), canvas area = 984px wide. Pill at `bottom-4 left-4` is well clear of all edges.
- Settings panel collapsed: canvas area = `100vw - 40px`. No change to pill positioning needed; the pill anchors to the canvas container, not the viewport.

## Copywriting Contract

### All i18n strings for Phase 2 UI surfaces

**Namespace:** `moshpit.assets.*` in `src/locales/en/main.json`

These keys extend the existing `moshpit` object (which currently has `moshpit.workspace.*`, `moshpit.canvas.*`, `moshpit.commands.*`, `moshpit.sidebar.*`).

```json
"moshpit": {
  "assets": {
    "processing": "Processing {done} / {total}",
    "cancel": "Cancel processing",
    "excludedCount": "{count} asset excluded: no metadata | {count} assets excluded: no metadata",
    "excludedTooltip": "Assets are excluded because they don't contain parseable ComfyUI metadata. Moshpit only renders generated images with embedded workflow data.",
    "excludedTooltipLabel": "Why are assets excluded?",
    "processingComplete": "Processing complete"
  }
}
```

**ICU plural pattern for `excludedCount`:**

Vue i18n plural syntax (pipe-separated): `"{count} asset excluded: no metadata | {count} assets excluded: no metadata"` — singular when `count === 1`, plural otherwise.

**Usage:**

```typescript
t('moshpit.assets.excludedCount', count) // count = N; vue-i18n selects singular/plural
```

### Full copywriting contract table

| Element                    | i18n Key                              | Copy                                                                                                                                              | Notes                                                                              |
| -------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Pill count text            | `moshpit.assets.processing`           | `"Processing {done} / {total}"`                                                                                                                   | Parameters interpolated from store                                                 |
| Cancel button `aria-label` | `moshpit.assets.cancel`               | `"Cancel processing"`                                                                                                                             | Screen reader only; no visible label                                               |
| Excluded count row         | `moshpit.assets.excludedCount`        | `"{N} asset excluded: no metadata"` / `"{N} assets excluded: no metadata"`                                                                        | ICU plural                                                                         |
| Info icon `aria-label`     | `moshpit.assets.excludedTooltipLabel` | `"Why are assets excluded?"`                                                                                                                      | Screen reader label for icon                                                       |
| Info icon tooltip body     | `moshpit.assets.excludedTooltip`      | `"Assets are excluded because they don't contain parseable ComfyUI metadata. Moshpit only renders generated images with embedded workflow data."` | Tooltip content                                                                    |
| `processingComplete`       | `moshpit.assets.processingComplete`   | `"Processing complete"`                                                                                                                           | Reserved for future `aria-live` announcement at completion; not displayed visually |

**Primary CTA:** There is no CTA in Phase 2 UI surfaces. The `×` cancel is a control affordance, not a call-to-action.

**Empty state:** The processing indicator is hidden on warm cache (D-08). There is no "empty processing" state visible to the user — the pill simply does not appear. The `MoshpitSettingsPanel` excluded-count row is hidden when `excludedCount === 0`.

**Error state:** Thumbnail pipeline errors surface via `console.warn` in the worker bridge. No user-visible error state is defined for Phase 2 UI surfaces. Failed assets are treated as excluded (they produce no sprite and do not increment `excludedCount` — they are silently skipped). Phase 7 UX edges may revisit this.

**Destructive actions:** Cancel is not destructive (it is resumable on re-entry per D-06/D-07). No destructive confirmation pattern is needed in Phase 2 UI surfaces.

## Open Questions

The following require resolution before or during Phase 2 planning/execution. They do not block writing the UI-SPEC but may require minor spec revision.

### OQ-1: Figma coverage gap (confirmed)

The Comfy Design Standards Figma file (`QreIv5htUaSICNuO2VBHw0`) has no Moshpit-specific indicator, pill, or overlay section. No Figma node ID exists for the processing pill or excluded-count row.

**Resolution:** This spec derives the pill chrome directly from existing Moshpit semantic tokens (`--interface-panel-surface`, `--interface-stroke`, `--color-interface-panel-job-progress-primary`) and from the repo overlay precedent (`NightlySurveyPopover.vue`: `bg-base-background border-border-subtle shadow-lg`). The pill uses `bg-interface-panel-surface` (panel surface) rather than `bg-base-background` (content surface) to match the sidebar/panel family.

**Action:** Recommend surfacing this to a designer before Phase 3 (when the filter chip bar and sort toolbar require more considered indicator chrome). For Phase 2, the derived tokens are the contract.

### OQ-2: Tooltip library alignment

`v-tooltip` is the PrimeVue directive, and CLAUDE.md says "no new PrimeVue usage." The directive is already globally registered and used extensively in the repo (`SidebarIcon.vue`, sidebar tabs). The instruction targets new PrimeVue component imports, not the already-registered directive.

**Resolution:** `v-tooltip` is acceptable for the excluded-count info icon because it is a global directive, not a component import. The executor should verify no `import Tooltip from 'primevue/tooltip'` is needed (it should already be registered). If Reka UI ships a tooltip primitive that is already wired in the project, that may be used instead — the visual contract (floating label above the icon) is identical.

**Action:** Executor to confirm `v-tooltip` is globally registered without a new import in the Phase 2 component. If not, use Reka UI `TooltipProvider` + `TooltipContent` pattern from the existing Reka UI integration.

### OQ-3: Cancel micro-state copy

The spec locks the cancel behavior as: click `×` → emit `cancel` immediately → pill stays until store resets. No "Cancelling…" intermediate copy.

**If the worker abort takes more than ~300ms** (unlikely at concurrency-4, but possible on slow connections), the user sees a pill frozen at N/M for up to 300ms after clicking `×`. This is an acceptable UX tradeoff for v1.

**Action:** If Phase 2 dogfooding reveals a jarring frozen-pill moment, the planner can add a `isCancelling` state that grays out the pill or shows "Cancelling…" — but that requires a new i18n key (`moshpit.assets.cancelling`). Reserve the key but do not implement it unless testing reveals the need.

### OQ-4: Progress bar width transition and `done/total` reactivity edge case

When `total` changes mid-processing (filter-change scenario, RESEARCH.md §6), the fill width can jump backward (e.g., `40/60 = 66%` drops to `40/80 = 50%`). The 300ms `transition-[width]` will animate the regression smoothly, but it may look like progress went backward.

**Resolution:** This is intentional — the filter change genuinely reduces the total, and showing the regression is honest. No special handling needed. The pill N/M count updates simultaneously and provides context.
